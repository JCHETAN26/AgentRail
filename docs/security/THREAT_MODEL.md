# Threat model

**Scope: Phase 15.** This document describes the system as built. It is updated in the same pull
request as any change that moves a trust boundary.

The platform has authentication, organisations, roles, tenant isolation, policy approval, release
webhooks, canary records and run-level observability. Every endpoint under `/api/v1` except the
sign-in and GitHub webhook routes requires a credential, and every tenant-owned row is scoped to an
organisation.

What is still missing is stated plainly below: the durable quota ledger currently covers monthly
evaluation item usage only. PostgreSQL row-level security exists as defence in depth and authorised
API/tenant-specific worker paths bind its transaction-local tenant context. The updated Phase 8
Multi-Agent Safety Tribunal has prompt-versioned model-backed debate and replay scaffolding; model
prompt inputs now receive sandboxed evidence instead of raw untrusted text.

## Assets

| Asset                                | Why it matters                                                   |
| ------------------------------------ | ---------------------------------------------------------------- |
| Job records in PostgreSQL            | The authoritative record of what the platform did                |
| Side effects performed by the worker | In later phases these become real remediation actions            |
| Infrastructure credentials           | Database, Redis and (later) cloud and model-provider credentials |
| Correlation and trace identifiers    | Support diagnosis; must not leak user content                    |
| The CI/CD pipeline                   | Compromise here compromises every future deployment              |

## Trust boundaries

```text
 [browser] ──1──▶ [Platform API] ──2──▶ [PostgreSQL]
                        │
                        └──3──▶ [Redis] ──4──▶ [Worker] ──5──▶ [CloudOps sandbox]
```

1. **Untrusted → API.** All input is untrusted.
2. **API → database.** Trusted network in Compose; credentialled.
3. **API → Redis.** Delivery only; contents are non-authoritative by design.
4. **Redis → worker.** Message contents are untrusted: a message is a bare identifier and is
   re-validated against the database.
5. **Worker → sandbox.** Internal, but the sandbox treats its input as untrusted and is deterministic
   and side-effect free.

## Threats and current status

| #   | Threat                                            | Status                  | Mechanism                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --- | ------------------------------------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | Oversized request body exhausts memory            | **Mitigated**           | `MaxBodySizeMiddleware` counts streamed chunks rather than trusting `Content-Length`; 64 KiB cap → `413`. Tested.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| T2  | Malformed or hostile JSON reaches the domain      | **Mitigated**           | Pydantic models with `extra="forbid"`, length bounds on every string, enum-constrained `kind`. Tested.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| T3  | Stack traces or driver messages leak to clients   | **Mitigated**           | Every exception is translated to `ProblemDetail`; the traceback goes to the log only. Tested.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| T4  | Secrets leak into logs                            | **Mitigated**           | The JSON formatter redacts any field whose key matches a sensitive marker (`token`, `secret`, `password`, `authorization`, `prompt`, …), recursively. Tested.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| T5  | Duplicate delivery causes a duplicate side effect | **Mitigated**           | Conditional `UPDATE ... WHERE state = <expected>`; terminal states have no outgoing transitions. Tested with racing workers and tenfold redelivery.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| T6  | Client retry creates duplicate work               | **Mitigated**           | `Idempotency-Key` with a request fingerprint; reuse with a different body is rejected. Tested.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| T7  | Long-running query pins a connection              | **Mitigated**           | Server-side `statement_timeout` on every connection; bounded pool.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| T8  | Queue poisoning with a fabricated job id          | **Mitigated**           | The worker re-reads the row; an unknown identifier is dropped. Tested.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| T9  | Container escape via a root process               | **Mitigated**           | Images run as uid 10001. Asserted in the `containers / scan` CI job, alongside a check that the shared Dockerfile uses version-pinned runtime inputs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| T10 | Cross-origin browser access to the API            | **Mitigated**           | CORS allows one configured origin with an explicit method and header allowlist, and `allow_credentials` is on so the origin list is load-bearing — a wildcard would be rejected by the browser and is unrepresentable in settings. The session cookie is `SameSite=Lax`.                                                                                                                                                                                                                                                                                                                                                         |
| T11 | Secrets committed to the repository               | **Mitigated**           | `.env` is git-ignored; `.env.example` contains only local-only values; GitHub secret scanning and CodeQL run on every push.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| T12 | Vulnerable or hostile dependency                  | **Partially mitigated** | Committed lockfiles and `--frozen`/`--frozen-lockfile` installs make the dependency set reproducible, Dependabot raises version updates, and the container CI matrix uploads per-service SBOM/provenance artifacts for every Python image. The `dependency-review` gate is **not** in force: it warns and skips because the dependency graph is disabled, and it is therefore excluded from the required checks. **A pull request introducing a moderate-or-higher advisory can currently merge.** Enabling the dependency graph and adding the check to the required list closes this — see `docs/BRANCH_PROTECTION.md`.        |
| T13 | Unauthenticated access to any endpoint            | **Mitigated**           | Every `/api/v1` route except sign-in requires a session cookie or a bearer API key. Sessions are opaque, stored only as a one-way digest, `HttpOnly`, `SameSite=Lax`, `Secure` when deployed, and revoked server-side on sign-out. Tested, including replay of a captured token after sign-out.                                                                                                                                                                                                                                                                                                                                  |
| T14 | Cross-tenant data access                          | **Mitigated**           | Every tenant-owned row is scoped to an organisation. `authorize()` checks tenancy before permission, and both failures are indistinguishable; another tenant's resource returns 403, never 404, so identifiers cannot be enumerated. Covered by cross-tenant integration tests plus an exhaustive unit matrix. PostgreSQL RLS policies now cover organisation-owned, project-owned and project-child tables when `agentrail.organisation_id` is set, with an integration test proving raw SQL filtering. Authorised API principals and tenant-specific worker execution/aggregation paths bind that context transaction-locally. |
| T15 | Denial of service by flooding job creation        | **Partially mitigated** | Authenticated users and API keys are capped by a Redis-backed fixed-window rate limit. Evaluation-run creation also spends from a PostgreSQL-backed monthly item quota per organisation, charged in the same transaction that creates the run. Remaining gap: quotas do not cover every workload class yet.                                                                                                                                                                                                                                                                                                                      |
| T16 | Prompt injection through tool output              | **Not applicable yet**  | No model is invoked. Becomes live in Phase 2 with the injection scenarios, and is governed by the policy engine in Phase 10.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| T17 | Unauthorised high-risk tool execution             | **Not applicable yet**  | The only task is a side-effect-free no-op. Policy and approvals are **Phase 10**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| T18 | Forged or replayed GitHub webhook                 | **Mitigated**           | The receiver verifies the HMAC over the raw body before parsing JSON or doing work. Signed deliveries must include `X-GitHub-Delivery`, which is reserved in Redis with a short TTL; a duplicate delivery gets `409 replayed_webhook` before cancellation logic runs.                                                                                                                                                                                                                                                                                                                                                            |
| T19 | Stored XSS in the console                         | **Partially mitigated** | React escapes by default and `dangerouslySetInnerHTML` is not used anywhere. The console sends CSP, `X-Frame-Options`, `nosniff`, Referrer-Policy and Permissions-Policy headers. The CSP still permits inline/eval script because the current Next.js build shape needs it; tightening that requires nonce plumbing.                                                                                                                                                                                                                                                                                                            |
| T20 | Supply-chain compromise of a GitHub Action        | **Mitigated**           | Third-party workflow actions are pinned to immutable commit SHAs, with the source tag retained as an inline comment for reviewability. CI runs `scripts/check_github_actions_pinned.py` so a mutable action tag cannot be introduced accidentally, and the container job uploads image provenance tied to the exact repository, ref, commit SHA and workflow run.                                                                                                                                                                                                                                                                |
| T21 | Session token stolen from the browser             | **Mitigated**           | The cookie is `HttpOnly`, so JavaScript — including an XSS payload — cannot read it, and `SameSite=Lax` blocks cross-site POSTs from carrying it. `Secure` is set in deployed environments. The console never handles a token itself.                                                                                                                                                                                                                                                                                                                                                                                            |
| T22 | Session survives sign-out                         | **Mitigated**           | Sessions are server-side rows, revoked on sign-out. A captured token replayed after sign-out is rejected. Tested.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| T23 | Leaked API key grants broad access                | **Partially mitigated** | Keys are stored only as one-way digests, scoped to exactly one organisation, bounded by a role and optionally narrowed further by scopes, revocable immediately, rotatable in place, and optionally expiring. Rotation replaces the public key id and secret hash, returns the new token once and invalidates the previous bearer token immediately. The `ar_` prefix makes keys recognisable to secret scanners. Not yet mitigated: there is no anomaly detection on use.                                                                                                                                                       |
| T24 | Privilege escalation by minting a superior key    | **Mitigated**           | A key's role must be a subset of the creating principal's own permissions, checked at creation. Scopes intersect with the role rather than widening it, so a scope cannot grant what the role lacks. Tested.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| T25 | Passwordless dev sign-in reaches production       | **Mitigated**           | Three independent guards: `dev_auth_enabled` is false when deployed, the route rejects rather than advertising itself, and `ApiSettings` refuses to construct in a deployed environment without GitHub OAuth credentials. Tested.                                                                                                                                                                                                                                                                                                                                                                                                |
| T26 | OAuth callback replayed or forged                 | **Mitigated**           | A random `state` is issued and only its digest is stored in an `HttpOnly` cookie for callback comparison; a mismatch is rejected. GitHub emails must be both `primary` and `verified`, and accounts match on `(provider, subject)` rather than email, so a reassigned address cannot inherit an account.                                                                                                                                                                                                                                                                                                                         |
| T27 | Audit log tampered with or leaking secrets        | **Partially mitigated** | Audit events are append-only in application code and pass through the same redaction as the logger, so a token cannot be persisted. Organisation admins can prune events older than the configured retention window, scoped by organisation. RLS hides other organisations' audit rows when tenant context is set. Not yet mitigated: nothing at the database level prevents an operator with write access from editing rows in their own visible scope.                                                                                                                                                                         |
| T28 | Tribunal evidence causes prompt injection         | **Mitigated**           | Tribunal model-backed debate uses versioned role prompts, structured output schemas and fail-closed validation; deterministic Auditor blockers remain a safety floor. Model-backed role calls receive a sandboxed evidence envelope where arbitrary strings from run/comparison evidence and prompt overrides are reduced to digest/length metadata before they enter prompts.                                                                                                                                                                                                                                                   |

## Standing rules

These are review-blocking:

- Never log a raw secret, credential or prompt.
- Never put a real credential in `.env.example` or in a test.
- Never return a stack trace, driver message or internal path to a client.
- Never let Redis hold authoritative state.
- Never accept an unsigned webhook.
- Never store an API key in plaintext.
- Never describe synthetic sandbox output as real telemetry.
